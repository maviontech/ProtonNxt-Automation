# Public Submissions Smoke Test Suite

Source: Public_Submissions_Smoke_Test_Cases.xlsx. All 15 source cases are retained.

## Execution prerequisites

- Use a dedicated test tenant: URL lifecycle tests generate and revoke links; candidate tests create records.
- Provide admin credentials using the existing login configuration.
- Provide a separate unauthorized account for SMK-PS-015. Missing account data is reported as skipped.
- Pagination creates enough synthetic candidates to exceed the selected page size when existing submissions are insufficient.
- Each test prepares its own prerequisites; execution order is not required. Existing active links are never revoked by setup.

Run: `python -m pytest tests/smoke/test_public_submissions_smoke.py --headless`

Report runner: `./run_public_submissions_smoke_report.ps1`.

To allow revocation of existing links in a dedicated test tenant, set
`$env:PROTONNXT_PS_ALLOW_REVOKE_EXISTING='true'` before running. Otherwise cases
002–004 and 012–013 skip when an existing active link needs to be preserved.
Links generated by fixtures are revoked during cleanup. Submitted candidate
records remain available for review; tests do not delete candidates.

Configure `PROTONNXT_PS_UNAUTHORIZED_USERNAME`, `PROTONNXT_PS_UNAUTHORIZED_PASSWORD`,
and optionally `PROTONNXT_PS_UNAUTHORIZED_COMPANY_CODE` locally for case 015.
Do not store account passwords in the suite or workbook.

Candidate data and pagination size are configurable in
`testdata/public_submissions_smoke_data.json`. Tests generate unique names, emails,
phone numbers and valid DOCX resumes. Run this suite serially because the tenant's
active URL is shared. Counter checks assume no concurrent external submissions.

The Excel suite in `tests/testcases/Public_Submissions_Smoke_Test_Suite.xlsx`
retains the original cases and adds a case-to-automation mapping sheet.

## SMK-PS-001 - Verify Public Submissions admin page loads successfully

**Priority:** High

**Preconditions:** Admin user is logged in and has permission to access Public Submissions.

**Steps**

1. Open Public Submissions from Recruitment Tasks.
2. Observe page load and main sections.

**Test Data**

Admin URL: /public-submissions/admin/

**Expected Result**

Page loads without error. Public Submission URL and Recent Submissions sections are visible, with Generate URL shown when no active URL exists.

## SMK-PS-002 - Verify Generate URL confirmation is displayed

**Priority:** High

**Preconditions:** No active public submission URL exists.

**Steps**

1. Click Generate URL.
2. Observe the confirmation dialog.

**Test Data**

N/A

**Expected Result**

A confirmation prompt appears asking whether to generate a new public submission URL, with confirm and cancel actions.

## SMK-PS-012 - Verify Revoke action disables active public URL

**Priority:** Critical

**Preconditions:** An active public submission URL exists.

**Steps**

2. Confirm the revoke action if prompted.

**Test Data**

**Expected Result**

URL is revoked successfully. Admin page no longer treats it as active, and the revoked public URL cannot accept new submissions.
